Claude preflight checklist

Before Claude creates anything new:

1 · Search the codebase.Find the exact existing script, table, function or connector that should answer the question.
2 · Check the upstream source.Supabase absence does not prove Oviond/Meta/Google absence.
3 · Extend, don’t duplicate.If the field exists upstream, add it to the existing ingestion path.
4 · Prove the full path.Source → ingest → persist → Brain → UI → Ask Vantage → real Easley test.
5 · Label dependencies honestly.If no real resource exists, say what must be added instead of mocking the result.

1. Resolve location firstSupabase Auth → organization_memberships / location_memberships → locations.id. Every downstream read/write must be tenant scoped.
2. Resolve Oviond sourcedashboard_mappings.oviond_client_id maps Vantage location to the correct Oviond client.
3. Ingest through the existing syncsyncOviondClients.js remains the primary source-ingestion path. Do not create frontend-side source fetches for data that belongs in Supabase.
4. Paid historical baselinehistorical_metrics powers spend/click/CPC/CTR history and business-specific baselines.
5. Organic contentsocial_posts powers post-level performance and content/theme intelligence.
6. Budget / pacingcampaign_budget plus new Meta budget fields powers current pacing. Periods must match actual spend windows.
7. Meta creative / best adOviond ad/adset/ad_creative fields are available upstream but must be persisted before production. “Best” must be objective-aware, not CTR-only.
8. Local intent / GBPUse the existing local-visibility ingestion for directions, calls, Maps/search actions and website activity. Claude must verify exact persisted table names in code.
9. Competitor / rank intelligenceUse the real existing competitor/rank-grid implementation already working in the codebase. Verify exact table/function names before wiring. Do not invent a duplicate system.
10. Source healthconnection_health must be checked before Vantage says data is missing, zero, or stale.
11. Brain processingrunBrainForAllLocations.js + location_brain_state + current signal/investigation machinery remain the reasoning path. Improve this layer rather than creating a second analyzer in the UI.
12. Historical → predictive logicCurrent signals are compared against historical_metrics, social_posts, local-visibility history, rank/competitive history and later Store Pulse/POS. Predictions require a traceable evidence chain.
13. Landing-page journeyTagged landing pages → GA4 / Google tag events → Vantage ingestion. Track product/offer views, call/directions clicks, form/finance actions and campaign lineage where lawful.
14. Store Pulse / local events / owner contextPersist owner-entered walk-ins, sales, revenue, products sold, inventory notes, promotions and local events in tenant-scoped Supabase tables with timestamps and provenance.
15. POSSupported POS integrations use secure authorization. Unsupported systems fall back to upload/report/manual Store Pulse. Never fabricate a direct connection.
16. Prediction / experiment memoryPersist evidence refs, confidence, expected outcome, disproof condition, due date, decision, actual result and learning. This powers hindsight and future judgment.
17. Ask VantageChat retrieves the same current Brain state, active signals, investigations, history and owner/store context that power the visual experience. It must not independently invent a separate interpretation.
18. Full PictureDeep views resolve from the same evidence references used by the top-level thought. No disconnected calculations.
19. Frontend ruleThe UI renders intelligence. It does not decide business truth. Missing backend support should be surfaced as a dependency rather than mocked.
20. Proof before productionFor each feature: source confirmed → ingested → persisted → Brain uses it → frontend receives it → Ask Vantage can explain it → tested on Easley with real data.
